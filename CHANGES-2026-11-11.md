# Changes from review comments (11 Nov 2026)

| Comment | Change |
|---|---|
| Sub-city, woreda and kebele should be set up on the admin side and used when creating an account | New page **Sub-cities, woredas & kebeles** (`/staff/locations`). Admin adds sub-cities (with sub-city mayor), woredas per sub-city and kebeles per woreda (comma-separated for bulk entry), and can rename or deactivate them. Account registration, walk-in case registration, walk-in appointment booking and admin-created case-owner accounts now use linked drop-downs (Sub-city → Woreda → Kebele). The server rejects combinations that are not on the admin's list. |
| Track with reference number OR phone; if a phone has several cases, let the person choose | `/track` accepts either field. A reference number opens that case. A phone number with one case opens it; with several, a list of reference numbers with type, category, date and status is shown, and the person chooses one. Phone formats 09…, +251… and 251… are treated as the same number. |
| Admin dashboard: no need for this (Recent activity) | Removed from the System administration dashboard. The full Audit log remains in the menu. |
| Department page | Now **Departments / offices**: code generated automatically (OFF-001, …); "Type" replaced by **Office** (office name); **Name of head of office representative**; **Sub-city** drop-down; **Sub-city mayor** instead of Head (fills in from the chosen sub-city and is kept on the sub-city, so all its offices show the same mayor). |
| Roles & permissions could not be changed and saved | Rebuilt as an editor: choose a role, tick/untick permissions, press **Save permissions** (confirmation message shown). **Restore defaults** per role. Safeguard: the Super Administrator role cannot lose role management. |
| Staff accounts: create accounts for individuals such as case owners from inside | **Accounts** page now has two tabs: *Staff* and *Case owners (citizens)*. Admin can create a case-owner account (temporary password, must change at first sign-in), see all case-owner accounts with phone, location and number of cases, deactivate/activate them and reset passwords. If the person already has walk-in cases under the same name and phone, they are linked to the new account (the same happens when someone self-registers). |

## Database

- New tables `Woreda`, `Kebele`; new column `SubCity.mayorName`; `Department.type` defaults to `OFFICE`.
- Development (SQLite): `npx prisma db push` then `npx prisma generate`. The included `prisma/dev.db` has already been updated and given demo woredas 01–03 / kebeles 01–03 for each demo sub-city.
- Production (PostgreSQL): `npx prisma migrate deploy` applies `prisma/migrations/0002_locations_offices` (the Docker image does this on start).

## After unpacking

1. `npm install`
2. `npx prisma generate` and `npx prisma db push` (SQLite) - or `npx prisma migrate deploy` (PostgreSQL)
3. `npm run dev`, or `npm run build` then `npm start` (the old `.next` build folder was left out because it was built from the previous code)
4. `npm test` runs the test-suite, including new tests for these changes ("Review changes (Nov 2026)")

# Second round (11 Nov 2026)

| Comment | Change |
|---|---|
| Keep only Super Administrator, Mayor, Deputy Mayor, Head of Mayor's Office, Secretary, Department Head | The other five roles are removed. Their work moves to: **Secretary** (case registration/verification, walk-ins, correspondence; can be case officer), **Head of Mayor's Office** (review, case-officer assignment, forwarding, closing), **Department Head** (works on and responds to department cases directly). The Citizen role stays, as it is the portal account for case owners. Running `npm run db:seed` (done automatically by Docker on start) moves any existing users of a removed role to its replacement and deletes the old roles. |
| Category not listed and sub-city empty on the citizen "Submit a case" page | Production installs had no categories because they were only created with demo data. Nine standard categories (in English, Afaan Oromoo and Amharic) are now created automatically when none exist, both by the seed and the first time the form is opened; edit them under Case categories. Sub-cities come from the admin page "Sub-cities, woredas & kebeles" — add yours there. The form now pre-selects the citizen's own sub-city and explains when a list is empty. |
| After a case is submitted and the dedicated person is assigned in the Mayor's Office, they should give an appointment; the citizen can see it and request one, and get it approved | **Case officer**: on the staff case page the Head of Office assigns the case officer (Head of Office or Secretary). The citizen and officer are notified and the citizen sees the officer's name. **Give an appointment**: the case officer picks a free slot and writes a message; it is confirmed immediately. **Request an appointment**: on the citizen's case page, once an officer is assigned, the citizen picks a free slot with that officer. The request appears on the staff case page, where the officer can approve it or reject it with a reason. Every step is logged in the case history (visible to the citizen), notified, and shown in both appointment lists. |

Database: `Appointment.caseId` added (`prisma/migrations/0003_case_appointments`). The included `dev.db` is already updated.

Also fixed: a duplicate translation key (`view`) introduced in the first round.
